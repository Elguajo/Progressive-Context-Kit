# Как работает Progressive Context

> **Документация только для человека.** Она живёт только во Framework Source и не попадает в Project Runtime.
>
> English: [`HOW_PROGRESSIVE_CONTEXT_WORKS.md`](HOW_PROGRESSIVE_CONTEXT_WORKS.md)

Progressive Context Kit строится вокруг одного правила:

> **Минимизировать активный контекст, а не доступные знания.**

Смысл не в том, чтобы проект «знал меньше». Смысл в том, чтобы новая AI-сессия не загружала всё, что проект когда-либо накопил.

## Базовая модель

Схема: [`../visuals/progressive-context-overview.md`](../visuals/progressive-context-overview.md)

Знания проекта концептуально делятся на два слоя:

- **active / hot context** — минимальный набор для понимания продукта, текущей системы, текущей Phase и непосредственной задачи;
- **cold / on-demand context** — подробная история и evidence, которые остаются доступными, но читаются только при необходимости.

Обычная сессия должна восстанавливать примерно такой путь:

```text
repository behavior
→ PROJECT_BRIEF
→ ARCHITECTURE
→ ROADMAP
→ текущая Phase
→ компактный Completion Record предыдущей Phase, когда это нужно
→ релевантный код/тесты + подходящий Skill
```

Она не должна рекурсивно читать все завершённые phases, ADR, completion reports, human guides или framework-development файлы.

## Поток новой сессии

Схема: [`../visuals/session-context-flow.md`](../visuals/session-context-flow.md)

Новая сессия сначала восстанавливает минимально достаточное и надёжное состояние, а затем расширяет контекст только тогда, когда задача требует дополнительных доказательств.

Это даёт сразу два свойства:

1. непрерывность проекта не зависит от chat history;
2. исторические знания не приходится удалять ради экономии токенов.

## Почему подробная история остаётся cold context

Завершённая Phase может иметь подробный Phase Completion Report, но обычное продолжение использует только компактный `Completion Record` как мост между фазами.

Если позже понадобятся точные детали реализации, агент может перейти по ссылке и прочитать только конкретный completion report.

## Почему это не просто summarization

Progressive Context — ещё и модель ownership + routing. Разные документы отвечают на разные вопросы, а разные типы задач активируют разные Skills.

Смотри:

- [`PROJECT_MEMORY_MODEL.ru.md`](PROJECT_MEMORY_MODEL.ru.md)
- [`../visuals/tool-routing.md`](../visuals/tool-routing.md)

## Какие проблемы эта модель должна предотвращать

- чтение всего репозитория перед каждой задачей;
- использование старого плана как текущей истины;
- бесконечное накопление истории в `NEXT_SESSION`;
- дублирование архитектуры в нескольких документах;
- загрузку всех установленных Skills для каждой задачи;
- потерю полезной истории только ради уменьшения context.

Итоговая цель: доступные знания проекта могут расти, но объём каждой новой сессии не обязан расти вместе с ними.
