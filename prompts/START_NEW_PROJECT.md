# Start New Project

Use for a new/greenfield product idea. Existing product repositories must use `ADOPT_EXISTING_PROJECT.md`.

1. frame durable product outcome/users/scope/constraints/success in Project Brief;
2. verify current primary docs only for architecture choices whose freshness matters;
3. choose one pragmatic architecture and record it compactly;
4. create a Roadmap with exactly one `[>]` phase and only as many phases as needed;
5. create phase files without copying Brief/Architecture prose;
6. add non-obvious context/Skill hints to `CONTEXT_MANIFEST.json` only when useful;
7. classify project Tier/Risk and run `tooling-bootstrap` when Recommended/Advanced tooling materially helps;
8. begin the current phase unless blocked by a user-only decision/approval;
9. verify evidence; when a phase completes, persist its Completion Record before advancing the Roadmap;
10. overwrite NEXT_SESSION with compact current-state handoff.

Ask only when product input is absent or a choice materially belongs to the user.
